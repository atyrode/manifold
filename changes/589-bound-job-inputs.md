A job can now be handed another job's sealed output as a declared input, so data flows between plugins' jobs without leaving the machine. The producing operation declares `exports` — which of its own outputs another plugin's job may bind, reviewed and consented with the rest of its declaration — and the consuming operation declares `inputs`, the names it reads. A request binds them with `inputs: [{ name, from: { jobId, output } }]`, and the workload finds each one at `/inputs/<name>`: a read-only directory holding that archive extracted, a real filesystem to walk and search rather than a page loop through the hub. The hub admits a binding only when the name is declared, the source job is a settled job of the same machine that sealed that output, the source operation exports it or belongs to the same plugin, and the requesting principal holds `jobs:read` at the source job's node — refusing `unknown_input`, `input_source_unavailable`, `input_not_exported`, `input_authority_refused` or `duplicate_input` by name, and asking all of it again if the start was deferred. Extraction is bounded by the new `limits.inputBytes`, which defaults to the operation's own `outputBytes`, happens before the sandbox exists so a missing, corrupt or oversized archive refuses instead of half-feeding a job, and is removed when the job settles; operators sizing the `runtime` tmpfs should now budget for inputs beside named outputs.
