---
section: Breaking Changes
issue: 602
---

Installed bundles without a hardened contract stamp are held until repacked once with a current plugin kit; the plugin manager names the minimum contract before any code loads. Additive-compatible native owners and bundles keep serving across hub upgrades, while incompatible owners retain their drain and retirement path. Development and production switches now require an installed-bundle candidate gate, and a successful development deploy dispatches its preview-owner pin update separately from production fleet pins.
An explicit, default-off bootstrap gate input permits the first upgrade of a target predating the export door only after an authenticated unknown-action refusal, with a visible warning and summary receipt. Existing export doors always run the normal gate; development dispatch keeps forward deployment and guarded rollback as separate operations.
