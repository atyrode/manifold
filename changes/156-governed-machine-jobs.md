---
section: Breaking Changes
issue: 156
---

Plugins can declare pinned machine artifacts, native terminal runtimes and bounded worker operations under explicit installation, resource and invocation consent. Readiness reflects the proved owner and each operation's current tools, anchors and scoped services, not terminal connectivity. The plugin manager exposes exact resource bindings and caller-to-callee approvals; mounted container authoring places governed terminals in canvases and compositions. Native service configuration uses compare-and-set promotion; projected read operations need scoped service authority rather than an arbitrary execution grant, and each upstream request is reauthorized and attributed before I/O. Action delegates retain the original caller's grants, scope and revocation. Source credentials remain behind native references, while runtime services use acknowledged, workload-owned private listeners and parent-bound native jobs. Linux jobs require held filesystem mounts, cgroup containment and seccomp; unavailable backends refuse execution rather than falling back to ambient programs. Private writable homes admit explicit sealed configuration, and terminal ownership and output sealing require positive workload-empty proof. Maintenance also waits for pending direct service mutations. Input requests use fresh correlated IDs and owner-confirmed cursors; asynchronous receipts distinguish accepted input from unknown delivery without replay. Protocol 28 requires matching governed owners; terminal-host IPC remains protocol 1, and compatible terminal-only transports and protocol-27 federation peers remain supported. Upgrade target hubs and safely quiesce affected native owners before replacing their binaries; source publication authorizes neither hub promotion nor fleet installation.
Scoped runtime HTTP requests use an ownership-proved established connection, with no
reconnect to a cached port. Another workload taking over a released listening port
cannot receive the runtime's subsequent scoped request data or bearer.
Owner-declared credential references can remain in integrity-protected root-managed
directories; the credential files themselves remain private and owner-held. Plugin
development can prepare generated worker bundles through the native development loop,
without introducing a second watcher or installer.
Protected credential paths require traversal, not directory-listing access; pinned
directory identities preserve exclusion checks and durable state commits. Native
owner shutdown releases the runtime-owned listener socket exactly once.
