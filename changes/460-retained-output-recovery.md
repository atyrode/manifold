# Keep retained output responsive during transport recovery

Native owners publish installation readiness from their last observed resource inventory instead of recursively scanning every declared tool tree when a transport reconnects or configuration is replayed. Large shell and Git closures no longer monopolize the owner control loop while retained output requests are waiting.

This changes observation, not execution authority: job admission, the final pre-spawn check and live service authorization still refresh the resources they require. No output timeout or private-file custody check is relaxed.
