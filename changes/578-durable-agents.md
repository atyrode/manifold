---
section: Breaking Changes
issue: 578
---

Agents are now durable, sponsor-owned identities with standing grants and harness context; each invocation is a separately bounded Run. Register an Agent with `core.access.registerAgent`, then use `createRun` or `createChildRun`; the old `createAgentRun`, `listAgentRuns` and `inspectAgentRun` actions are removed in favor of `listRuns` and Run-id-only `inspectRun`. Trusted runners receive Run credentials while browser admission returns no bearer, and harness launch keeps credentials out of public runtime metadata. The Agents section separates Agent and Run navigation from human Sessions, and run-scoped inspection, renewal and cleanup no longer combine concurrent invocations sharing an Agent principal. External `taskRef` values remain explicitly labeled legacy task references, not typed harness sessions. Deploy the protocol-32 hub first, then upgrade spokes and native job owners (RPC 35). Protocol-30/31 transports remain connected for existing work, but harness-managed launches fail closed by name until both the transport and owner support private credential binding; no credential is stripped or sent to an older spoke. Existing terminals are not restarted to gain the feature.
