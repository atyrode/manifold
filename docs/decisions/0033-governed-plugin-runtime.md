## Execution and authority

A job is one non-PTY execution of a manifest-declared operation from an installed plugin's hash-pinned platform artifact. It is not a caller-supplied executable, shell string, environment or cwd. The operation declares its bounded input schema, fixed argv with typed argument slots (no shell interpolation), required named locations, network mode, output names, byte/time/process limits and whether it accepts a bidirectional byte stream. The latter carries a program protocol, not a second job lifecycle. Code's existing engine protocol can use that transport unchanged.

There is one generic job service and one registered, traced execution door. Product actions and schedules use the original credential/delegation lineage, not merely its principal ID. Nested invocation authority is distinct from resources possessed by the caller: an explicit edge names the exact callee operation/artifact, argument and output constraints, concurrency/depth and aggregate bounds. The host binds actor, caller plugin, parent job and edge. Admission intersects current credential authority, its original immutable ceiling, caller consent, callee consent and that edge; Code's provider resources never become Babel's possessed resources. Machine labels confer no authority; re-enrollment creates a new target.

Invocation output rules are exactly `{ name, locationId, components, maxSuffixComponents }`. A zero suffix bound requires an exact path; a positive bound requires one through that many additional components beneath the prefix, with at most 16 total. Names are unique, every rule matches one child output and location IDs match exactly. Child requests still carry exact immutable `{ name, locationId, components }` bindings, not the broader rule. The operation's bounded input declaration remains the argument contract; an edge is not a caller-supplied shell or an alternate input schema.

Use the existing permission waterfall, not an execution ACL alongside it. Validate bounded targets first, resolve existing canonical machine/job/resource/output nodes, then discharge every requirement through the common evaluator. Never disguise a machine ID as a container ID or perform only a root-cap check. The evaluator returns the winning grants and their durable revisions as decision evidence. Explicit artifact/resource-version-bound execution, invocation, location and network consent is required even for root and first-party operations; absence refuses. Do not backfill it from wildcard grants, plugin enablement, enrollment or the installer's existing default-cap algorithm.

Raw paths are not public grants. Manifests declare namespaced locations and reviewed platform-resolution data. The agent resolves against its own account/platform/XDG facts, not caller environment. Rights distinguish read, write and create. Missing/unsupported/ambiguous resources refuse. Pin admitted directories and resolve every descendant through held handles with no symlink, magic-link or mount escape. Parent directories and adjacent session-store authentication files are not implied grants.

The machine runner is a separate supervised owner, not the PTY implementation disguised as a job. Its authority and state are inaccessible to a confined child. Linux uses pinned bubblewrap with FD-backed mounts from held directory/file handles, isolated PID/IPC/user namespaces, dropped capabilities and a fresh explicit environment. The owner controls the enforcing cgroup-v2 ancestor; a child sees only its bounded nested workload delegation. Never inherit daemon enrollment tokens, hub keys, unrestricted HOME or caller environment. Unsupported platforms or unavailable enforcement refuse before process creation; listing an artifact platform is not evidence of an implemented confinement backend. A same-UID unrestricted host process or administrator is outside this confinement boundary; 0700 alone never proves isolation. No privileged jobs or passwordless sudo in this contract.

Network access is denied by default. Any host-network exposure is a separate explicit high-risk resource, never implied by a filesystem grant or labelled restricted egress. Artifact acquisition occurs in the trusted runner and does not grant download/network authority to the child. Code retains ownership of its own model/OMP containment, tool authority and provider-credential handling.

Babel invokes Code as a separately authorized child job, with separately resolved resources and the original credential/parent binding. The generic runner supplies bounded bidirectional byte transport and a narrow output lease, not provider credentials; Babel consumes it through the same worker supervisor. Leases identify output nodes, never arbitrary host paths, and reads/purge require the common evaluator rather than opaque-ID possession. Collection resolves every entry beneath held directory handles, accepts only bounded regular files, rejects links/unsafe types, and never reopens a checked pathname. Seal output only after all authorized writers/descendants release it, then atomically publish immutable bytes/digests. OMP still receives no writable host mount.

`child_exit` explicitly carries `outputsSealed: false`; it reports observed execution, not closure proof or the final sealed result. Parent-held child-output leases can keep output writable after the child exits. Final publication must wait for every authorized writer/descendant to release, not merely the direct process exit.

## Lifecycle and durability

Persist canonical request content and its credential/delegation reference before admission: immutable scope/expiry ceiling, actor, authenticated machine, operation/artifact, validated argument digest, resources/outputs, bounds, parent and invocation edge. Hub and machine bind job ID to that digest; changed content refuses, exact duplicate returns its prior state. A durable job-owner identity, signing key and generation fence executions independently of terminalHostId and PTY inventories. A hello with zero terminals proves nothing about jobs. Keep deduplication tombstones after result/output expiry, or retire an issuance epoch so every old ID can only be refused; bounded retention must not permit old effects to execute again.

States distinguish queued/admitted, start-committed, started, exited, interrupted/unknown, cancelled and refused. Hub transport and workload-owner lifetimes are independent. The machine persists its start reservation before process creation and persists its result before acknowledgement. A crash between reservation and observation remains unknown and is not automatically executed again. Exit 0 is process success, not verified product effects. Product plugins supply postconditions.

Queued work requires live just-in-time authorization. In a short transaction, re-read credential revocation/expiry, current grants, consent/enablement, invocation edge, machine/job-owner identity and policy revision; atomically commit a decision and short-lived single-use permit bound to the immutable request and executor. The machine durably consumes that permit once before spawning. Revocation/expiry before this start-commit point yields zero starts. Do not promise instantaneous distributed revocation between commit and a later syscall. Revocation also requests cancellation of committed work; record what occurred. Persist original credential reference, requesting plugin/parent, requirement nodes, winning grant IDs/revisions, consent/artifact revision, commit time and fenced executor; process-local grantsEpoch is not an audit policy version.

Cancellation is idempotent, closes input and terminates the whole execution tree with bounded grace, then reports the observed result. A lost channel is not success. The owner retains workload and bounded result state across transport/hub restart; after owner restart reconcile durable reservations without pretending an unobserved effect did not occur. Maintenance drain must close job admission as well as its existing terminal admission duty without merging the two workload lifecycles.

Stdout/stderr are bounded, typed, sequenced byte channels. Durable public results contain lifecycle, attribution, digest/count/limit facts and authorized output references, not raw inputs/prompts/transcripts/stderr. Generic runtime doors use `trace: "opaque"` before validation/auth refusal or journal writes, suppressing raw request/result bodies rather than trusting handler redaction. Lifecycle records append safe metadata linked to the original trace, with distinct action/invocation/schedule origins. `ctx.jobs.follow` and hardened `GuestJobs.follow` expose bounded replay snapshots and sequenced live updates under current authority: 128 events/256 KiB per job, explicit unavailable ranges and gap/authority/consumer closure. This is not a durable transcript or a reason to poll status. Products retain their own private evidence; public streams should carry only safe metadata.

Schedules use the same request/admission path and retain an explicit durable delegation plus its credential lineage and immutable authority/expiry ceiling. They never acquire non-expiring authority by default or silently outlive their granting credential. Bind target identity, operation/artifact, policy and cadence; revocation/expiry disables future starts. Offline policy is skip or coalesce-one with a deadline. An occurrence identity includes schedule revision and nominal occurrence and is committed before enqueue. Artifact/machine replacement does not silently retarget an existing schedule. No privileged scheduling is introduced.

## Platform artifacts and installation

Optional machine halves declare per-platform HTTPS artifacts and SHA256. Acquisition itself has explicit approved destination authority: verify every redirect hop is HTTPS, bound redirects, refuse local/private services unless separately consented, and send no ambient credentials. An executable digest does not authorize arbitrary network side effects. For release archives, stream only the declared regular-file entry into fresh private staging under compressed/uncompressed/member bounds; verify archive and entry identity before atomic publication, rejecting links or path substitution. Installation records exact artifact/resource consent. Unknown platform, digest mismatch or undeclared operation refuses before spawn. Nix remains optional; no host package mutation is implied.

Operations declare at most eight named `runtimeTools`, resolved only to reviewed runtime closures or declared separately hashed bundled artifact files. These are not arbitrary host executables or PATH lookups. Tool files and the executable are acquired from real packaged bytes under the same private acquisition bounds; exact hashes must come from packaging, never placeholders.

Acquisition is atomic and private. Active executions pin their artifact; upgrades affect new admissions only. Disable stops admission and cancels active plugin jobs, retaining durable results/outputs according to declared policy. Re-enable does not replay jobs. Purge is a separate traced destruction with no active leases; never turn disable into deletion. Display consent and per-machine readiness/refusals through ordinary plugin surfaces; no engine product-specific branches.

Purge requires disabled installations, no active leases and proved online owners. The hub records `purge_requested` and releases references; neither that state nor command delivery is acknowledged physical deletion. A UI must not convert an installation acknowledgement into proof that machine bytes have been erased.

## Plugin-owned continuous streams

Streams extend the existing continuous-channel category on the one session socket. They do not turn frames into durable events or create another websocket/polling path. Preserve the existing terminal protocol's own semantics; this work adds a generic declared transport, not a second terminal renderer.

A manifest declares bounded `contributes.streams` descriptors: local ID, title, bounded body schema and maximum frame/ring/instance limits. Assembly owns a canonical plugin-qualified registry and refuses collisions, including reserved disabled contributors. Publication is exposed through a narrow plugin-bound context service; no arbitrary socket/room handle. A producer can only address an existing node owned by the plugin and declared stream kind. Opening/closing an authority-bearing producer is a traced lifecycle action; continuous frames produce no event-plane row.

Each instance has an unpredictable epoch and strictly increasing sequence. The server validates and bounds the body before adding it to a bounded ring. Subscription uses the existing node read-authority walk; re-discharge at delivery and after reconnect. Snapshot contains the retained window and explicit first/last watermark, followed only by later sequences. If the requested cursor predates retention or the epoch changed, send an explicit reset/gap; never synthesize missing data. This is live follow, not durable transcript retrieval.

Reuse the bounded session sender. A slow stream subscriber must not cause unbounded allocation or silently lose sequence continuity. Stop that subscription on overflow and deliver an explicit resync state when capacity returns; if control cannot be delivered within the transport budget, close the connection with a named reason so the existing SDK reconnect path reopens from its cursor. Healthy room traffic is not deliberately discarded. The SDK owns reference-counted subscriptions/reconnect on its existing pooled socket; a client stream handle exposes snapshot, cursor, gap/reset, status and close, and discards duplicates without concealing skips.

Disable terminates producer epochs and refuses new subscriptions; re-enable requires new epochs; purge drops bounded retained stream state. Permission loss releases subscriptions and prevents queued frames from leaking. In-realm and hardened server/web plugin contexts and plugin-kit exports receive the same capability, not a Babel-only escape hatch. Publish the descriptors and wire vocabulary through `/api/protocol` and existing registries.

Producers expose `onClose` to release their attached job-follow and other resources on close/disable/teardown, including across the isolation bridge. Hardened `GuestJobs.follow` supplies snapshot/live follow and an asynchronous close handle without PTY or polling substitution. Stream descriptors explicitly name node kinds and read capability; governed nodes cannot be exposed under weaker read authority.

## Proof and cutover

Protocol 26 is a coordinated hub, machine-spoke and federation cutover: machine and instance accepted sets contain only the current version. Instance shares carry the expanded closed capability/reference vocabularies, so federation cannot retain the older accepted set. There is no feature fallback, legacy terminal-program downgrade guard or alternate control path; incompatible peers are rejected at the existing version boundary. Release metadata/version mutations are a coordinated integration concern. No live rollout is performed or authorized here, and the proof requirements below are not a claim that gates have passed.

Required machine proof: real non-PTY job; denied actor/target/resource causes zero starts; revoked/expired queued authority causes zero starts; changed request and re-enrolled label refused; duplicates across disconnect and owner/hub restart do not execute twice; cancellation reaches descendants; artifact/link/credential boundaries are exercised; requester cannot edit runner policy/audit or inherit daemon/provider credentials; private child-job output handoff preserves hashes and grant separation; offline schedules obey their chosen catch-up rule.

Required stream proof: real plugin publishes 20 frames per second for a minute to a browser/SDK; ordered receipt and watermark handoff; explicit out-of-ring reset; delivery-time denial; bounded slow-consumer behavior; disable/re-enable epochs; zero event-journal rows per frame. UI proof must use the actual plugin surface after the backend contract is available.

Consumer closure remains outside the common floor: the companion implementation chain is OMP `native-closure/1`, then Code `code.capture/1` and `code.runtime/2`, then immutable capture references and encrypted sharedcatalog attachments. Process exit alone proves none of those postconditions. This record does not cite stock OMP or any older named revision as containing the new acknowledgement, nor claim independent verification of those implementations. Product contracts and their own evidence govern native custody; the generic runtime does not interpret their formats or providers.

## Foundation admission

The shared operation/resource and stream mechanisms extend existing protocol, transport, permission and plugin-host pillars. Bootstrap circularity: a remote machine half cannot supply the mechanism required to start or authorize itself, and a plugin cannot negotiate its own stream transport before the host exists. Neutrality: the floor recognizes declarations, opaque identities, bounds and nodes, not product names or operations. Arbitration: the host resolves competing declarations, grants, installed consent, workload ownership and delivery budgets. Product actions, postconditions and views stay in plugins. No new privileged activation surface or product-specific floor branch is admitted.

## Authority vocabulary

Use closed capabilities with canonical resource nodes, not a dynamic string capability or a parallel job ACL: machines:run, jobs:read, jobs:input, jobs:cancel, locations:read, locations:write, locations:create, operations:invoke and network:host. Operation/location nodes belong beneath their authenticated machine; jobs resolve to their admitted operation; output nodes belong to their job. Plugin-qualified IDs are declaration data. Every new execution/resource consent remains absent until explicitly granted for the exact artifact/resource revision.
